# codef KB국민카드 조회 조건 근거

[codef 도메인 안내](codef.md)의 하위 문서입니다(#45). KB국민카드(기관코드 `0301`)를 CODEF로 조회할 때 공급자가 설명한 조건을 셀 좌표와 함께 정리합니다. 이 문서는 근거 정리이며, 아래 조건을 코드로 옮긴 것은 [취소 표현 구분](#취소-표현-구분)뿐입니다.

## 근거와 한계

- 출처: Aside가 공식 공개 페이지와 공식 연결 시트에서 수집한 자료(관찰 2026-11-01T08:16:27Z).
  - 카드 개인 API 파라미터 상세 시트(13개 시트)와 공식 오류코드 페이지 전체 다운로드(587행, 고유 코드 586개)입니다.
  - 구현 작업자가 직접 브라우저로 확인한 것이 아닙니다.
- 근거 종류는 공식 명세(시트·오류 목록)입니다. 공식 SDK 구현을 근거로 삼지 않았고, **실제 응답 관측은 없습니다**.
- 시트에 적힌 한계를 그대로 옮깁니다.
  - `참고 승인내역 취소건!B1`: "본 문서는 참고용으로 제공되며, 카드사 사이트 구조 변경 등으로 인해 아래 명세와 실제 응답 데이터가 일치하지 않을 수 있습니다."
  - `기관별 개발현황!R1`: "2021.10.27 기준".
  - `참고 승인내역 취소건!C21`·`로그인!G35`·`보유카드!F26`·`승인내역!F56`·`실적조회!F39`: "최종 업데이트 : 2026.10.20".
  - 시트 파일의 생성·수정 속성은 내보내기 시각일 수 있어 API 버전이나 약관 효력일로 쓰지 않습니다.
- 인용은 `시트명!셀좌표` 형식입니다. 시트 표기: `O` 필수, `△` 옵션, `-` 미제공(`보유카드!B24:C26` 등). `●` 개발완료, `미제공` 대상기관 사이트에서 해당정보 미제공(`기관별 개발현황!B51:C52`).
- "필수여도 상세내역에 따라 필수가 아닐 수도 있음"(`승인내역!B51`), "옵션 및 미제공시 빈 칸"(`보유카드!B22`·`승인내역!B51`·`로그인!B31`)이므로 빈 값은 0원·0건·기본값이 아니라 값 없음입니다.

## 기관 코드와 지원 범위

- `기관별 개발현황!B3:R4`(B3:B4·C3:C4·D3:D4 병합): 순번 1, 코드 `0301`, 기관명 `KB카드`. 로그인 방식이 두 행입니다.
  - 3행(`E3` 인증서)과 4행(`E4` 아이디) 모두 `F`(등록여부)·`G`(보유카드)·`H`(승인내역)·`I`(청구내역)·`J`(결제예정)·`K`(한도조회)·`L`(카드론)·`M`(실적조회)·`N`(포인트조회)·`P`(승인내역 합계금액)·`Q`(후불하이패스)가 `●`입니다.
  - `O`(이율조회)·`R`(기명식 선불카드 승인내역)은 `미제공`입니다.
- `기관별 개발현황!B33:J33`: 같은 시트의 다른 표입니다. 32행 머리글은 `가맹점정보`(B~F열)와 `아이디비번 찾기`(H~J열)입니다.
  - KB는 가맹점정보 로그인 `비로그인`·`●`(`E33`·`F33`), 아이디비번 찾기 로그인 `비로그인`·`●`(`I33`·`J33`)입니다. 카드 조회 범위와는 별개의 서비스 행입니다.

## 로그인

- KB 열은 `로그인!J3`입니다.
  - 인증서 로그인: 인증서 der·key 파일·인증서 패스워드가 `O`입니다(`J8`·`J9`·`J10`).
  - 아이디 로그인: 아이디·패스워드가 `O`입니다(`J14`·`J15`).
  - 생년월일·추가인증 항목은 `-`입니다(`J16`, `J19:J23`).
- 카드소지확인(`로그인!B25`): "KB카드의 경우 <카드소지확인> 페이지 이동되는 경우가 있어 해당 케이스의 경우 '카드번호', '카드비번'의 입력을 통한 인증 후 내역 조회 가능".
  - 이때 필요한 값은 '카드번호 (전체)'와 '카드비번 (앞2자리)'입니다(`J11`·`J12`·`J17`·`J18` 주석).
- 오류 처리 예시(`로그인!B25`)
  - 필수 파라미터 미입력은 `CF-12401` 또는 `CF-12411`, 잘못된 값은 `CF-13002`(errorUser에 파라미터 이름)입니다. 시트의 예시일 뿐 분류 근거가 아니며, `CF-12401`은 #47(PR #48)에서 정정되어 현재 `UNCLASSIFIED`입니다.
  - 아이디 로그인의 `CF-12801`(패스워드 오류)은 오류 횟수를 확인할 수 있으면 userError에 횟수를 표시합니다.
- `로그인!J27:J28`(param Extended, SMS 인증번호)은 KB가 `-`입니다.
- `로그인!J33:J34`는 KB `-`이며, 이 표의 행 의미를 설명하는 머리글 셀이 없어 해석하지 않았습니다.

**입력별 취급(2026-11-01 정정, [D-14 원칙 9](../decisions.md#d-09d-14-확정-정책)):**

- 아이디 로그인의 아이디·패스워드: CODEF 연결 요청에서만 받습니다(미구현). 저장·로그·응답·오류 메시지에 남기지 않습니다. 처음 문구는 "BeONE이 수집하지 않는 입력"이었으나, CLAUDE.md 보안과 PRD §7은 연결 비밀번호를 연결 요청에만 쓰도록 허용하므로 D-14에 맞춰 고쳤습니다.
- 인증서(파일·패스워드): MVP에 넣을지 별도 결정이 필요하며, 허용하지 않은 상태입니다.
- 카드소지확인의 카드번호 전체·카드 비밀번호 앞 2자리: BeONE이 수집하지 않는 입력입니다(CLAUDE.md 보안). 이 경로는 지원 보류(수동 입력 대체)이고, CODEF를 쓸 수 없을 때 수동 입력 경로를 유지합니다.

시트에 필드가 있다는 사실은 수집 승인이 아니며, 입력 수집 기능·요청 DTO·파라미터 상수는 만들지 않았습니다. 응답에서 `CF-12108`(카드소지확인 필요, 오류 목록 249행)이 오면 `CARD_VERIFICATION_NOT_SUPPORTED`로 분류됩니다.

## 보유카드

- KB 열은 `보유카드!H3`(입력)·`H8`(출력)입니다. 입력은 기관코드 `O`(`H4`), 조회구분(카드이미지 포함여부) `△`(`H5`)입니다.
- 출력
  - `O`: 카드명(`H10`), 카드번호(`H11`, 주석 예시는 마스킹 형식), 사용자명(`H13`), 유효기간(`H15`), 휴면카드 여부(`H16`), 이미지링크(`H19`).
  - `-`: 카드구분(`H12`), 발급일자(`H14`), 상태(`H17`), 교통카드 여부(`H18`), 세션(`H20`).
  - 따라서 KB에서는 [`CodefHeldCard`](../../backend/src/main/java/com/beone/api/codef/CodefHeldCard.java)의 카드구분·발급일자·상태가 값 없음으로 남는 것이 문서와 맞습니다.
- 이미지 링크 예외(`보유카드!B22`): "KB국민카드 : 홈페이지 카드 상품 리스트에 없는 카드 상품은 이미지 미제공으로 이미지링크 결과값 빈값으로 제공". 이미지 링크는 BeONE이 옮기지 않는 필드입니다.

## 승인내역

- KB 열은 `승인내역!H3`(입력)·`H17`(확장 입력)·`H23`(출력)입니다.
- 입력: 기관코드·시작일자·종료일자·정렬·조회구분 `O`(`H4:H8`), 카드번호 `△`(`H9`, 카드별 조회 시), 카드명·일련번호 `-`(`H10`·`H11`), 가맹점정보 포함여부 `△`(`H18`).
- 조회 가능 기간(`승인내역!B14`): "최근 12개월 (국민, 삼성, NH(92일 단위), 씨티, 우리, 하나(3개월 단위), 수협(6개월 단위))". 공급자 설명으로만 기록하며 기간 계산·검증 로직은 없습니다.
- 출력
  - `O`: 사용일자·사용일시·카드번호·카드명·가맹점명·이용금액·결제방법·통화코드·승인번호·국내/외 구분·취소여부·시작/종료일자(`H24:H26`, `H28:H31`, `H33`, `H34`, `H36`, `H42`, `H47`, `H48`).
  - `△`: 카드번호1·할부개월·결제예정일·가맹점 사업자번호·업종·전화·주소·번호·취소금액·부가세·봉사료(`H27`, `H32`, `H35`, `H37:H41`, `H43:H45`).
  - `-`: 원화금액(`H46`)·세션(`H49`).
  - 따라서 KB에서는 [`CodefApproval`](../../backend/src/main/java/com/beone/api/codef/CodefApproval.java)의 원화금액이 `Absent`로 남는 것이 문서와 맞습니다.
- 취소여부 주석(`승인내역!H42`): "취소전표매입"의 경우 "전체취소"와 "부분취소"가 구별되지 않아 "1"(취소)로 제공.
- 취소 표현(`승인내역!H51`·`B52`)
  - KB 열 기본 표시는 `type1`입니다.
  - B52: "KB카드 : "취소전표매입" 의 경우 type2를 사용. "이용금액"을 음수로 표출하고, "취소금액" 빈값으로 표출."
  - 같은 칸에 "국민카드: 결제방법 "3"그외 에 선할인(할부건)이 포함됨"도 있습니다.
- 가맹점정보 예외(`승인내역!B53`): 가맹점정보 포함여부가 "1"인 경우 매출전표를 조회하지 않는 기관이 있어 일부 값이 미제공이며, 그 기관에 KB가 포함됩니다.

## 취소 표현 구분

공급자 설명(`참고 승인내역 취소건`):

| 셀 | KB 승인취소(C열) | KB 취소전표매입(D열) |
| --- | --- | --- |
| 3행 | 국민 (승인취소) | 국민 (취소전표매입) |
| 4행 취소여부 | 상태 | 상태 |
| 5행 이용금액 | 양수 | 음수 |
| 6행 취소금액 | 취소인 경우 승인금액 | (빈 칸) |
| 7행 부분취소 구분여부 | X | X |
| 9행 Type | Type 1 | type2 |

- `C4`·`D4` 주석: "전표취소(취소전표매입), 정상(전표매입) : type2 / 승인취소(승인취소), 정상(전표미매입) : type1".
- `C14`: type1은 한 건에 이용금액과 취소금액이 함께 출력됩니다. 실승인금액 공식이 적혀 있지만 "실승인금액은 API에서 제공하는 값이 아님"입니다.
- `C15`: type2는 승인 1건과 취소 1건으로 출력되고, 취소 건의 이용금액을 음수로 처리합니다.
- 예시: `I14`(type1 전체취소 5000/1/5000), `I15`(type2 승인건 5000/0/빈 값, 취소건 -5000/1/빈 값), `K14`·`K15`(부분취소).

[CodefCancellationFormDescriber](../../backend/src/main/java/com/beone/api/codef/CodefCancellationFormDescriber.java)는 이미 해석된 승인내역 한 건을 이 설명과 맞춰 [CodefCancellationForm](../../backend/src/main/java/com/beone/api/codef/CodefCancellationForm.java)을 돌려줍니다.

| 취소여부 | 금액 모양 | 결과 |
| --- | --- | --- |
| `1` 취소 | 이용금액 양수, 취소금액 = 이용금액 | `Type1Canceled` (I14) |
| `1` 취소 | 이용금액 음수, 취소금액 빈 값 | `Type2CancelRow` (I15 취소건·B52) |
| `0` 정상 | 이용금액 양수, 취소금액 빈 값 | `NormalRow` (I15 승인건). C4 주석상 type1·type2를 가르지 못함 |
| `2` 부분취소 | 무관 | 판단 불가 `PARTIAL_CANCEL_NOT_DISTINGUISHED` (C7·D7 X, H42 주석) |
| `3` 거절 | 무관 | 판단 불가 `STATUS_NOT_DESCRIBED` |
| 값 없음·목록 밖 | 무관 | 판단 불가 `CANCEL_STATUS_UNKNOWN` |
| `0`·`1` | 이용금액 없음·미해석 또는 취소금액 미해석 | 판단 불가 `AMOUNT_NOT_PARSED` |
| `0`·`1` | 그 밖의 조합(예: 음수 + 정상, 0원) | 판단 불가 `SHAPE_MISMATCH` |

- 기관코드가 정확히 `0301`이 아니면 `OrganizationNotDocumented`입니다. 다른 기관 열은 이번에 일반화하지 않았습니다.
- 이용금액이 음수라는 사실만으로 취소나 type2로 판정하지 않습니다. 결과에는 금액이 없고, 실승인금액·합계를 계산하는 메서드도 없습니다.
- 하지 않는 것: 승인 건과 취소 건의 매칭, 원장 반영, 실적 귀속, 한도 복원, 빈 취소금액의 0원 치환, BeONE 상태값 변환(D-04). 매칭·원장 반영·귀속 정책은 [D-17](../decisions.md#d-15d-16d-17-확정-정책)로 정했으며 아직 구현하지 않았습니다.

```java
// 합성 예시: 해석된 승인내역 한 건의 형태만 기술한다
CodefCancellationForm form = CodefCancellationFormDescriber.describe("0301", approval);
if (form instanceof CodefCancellationForm.Type2CancelRow) {
	// 취소 행 형태. 짝이 되는 승인 행을 찾거나 금액을 빼는 것은 이 단계의 일이 아니다
}
```

## 실적조회

- KB 열은 `실적조회!H3`(입력)·`H10`(출력)입니다.
- 입력: 기관코드 `O`(`H4`), 시작일자(조회기간 YYYYMM, default 당월) `△`(`H5`).
- 조회 가능 기간(`실적조회!B7`): "KB카드 : 최근 12개월까지 조회 가능". 공급자 설명으로만 기록합니다.
- 출력
  - `O`: 카드명(`H12`), 바로가기 링크(`H16`), 카드혜택 List(`H17`), 실적현황 List(`H21`), 기준이용금액(`H23`), 현재이용금액(`H24`), 시작일(`H26`), 종료일(`H27`), 상세내역 List(`H29`).
  - `△`: 실적 충족여부(`H22`), 필요실적금액(`H25`), 상세 혜택명·실적조건(`H30`·`H31`).
  - `-`: 카드번호·카드구분·카드사(`H13:H15`), 혜택 구분·혜택명·업종(`H18:H20`), 제공기준(`H28`), 세션(`H33`).
- 실적 충족여부 주석(`실적조회!H22`): "미제공 ex) 결제실적을 사용하는 경우 실적페이지에서 판단 불가".
