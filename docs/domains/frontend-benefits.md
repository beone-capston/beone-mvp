# 프런트엔드 혜택 조회

하단 혜택 탭은 카드별 월간 상태와 월별 모의 결제 원장에 접근하는 읽기 전용 화면입니다.

- [혜택 화면](../../frontend/src/benefits/BenefitsPage.tsx)은 메인의 포트폴리오 모드를 사용합니다. 조회월과 현황 화면의 선택 카드는 모드별로 메모리에 유지됩니다. 탭을 떠나거나 조회 대상이 바뀌면 요청을 취소하고, 취소 이후 응답을 화면에 표시하지 않습니다.
- [API 어댑터](../../frontend/src/benefits/api.ts)는 보유 카드·상품 목록·상품 상세·월간 상태·모의 원장·결제 상세를 GET으로 조회합니다. 시연 프로필은 기존 API 주소와 `X-BeONE-Demo-User`를 사용하고 쿠키를 생략합니다. 회원 프로필과 이를 사용하는 공개 프로필은 같은 출처에서 회원 쿠키를 사용합니다. 회원 조회는 내 카드에 한정됩니다.
- [화면 모델](../../frontend/src/benefits/model.ts)은 확인된 상품 매핑과 서버 보유 카드 ID를 구분합니다. 네 상품의 표시명 사전에는 이름만 들어갑니다. 한도 및 사용액은 서버 응답에서 읽고, 전월 실적과 규칙 기간이 일치할 때만 참고 한도를 표시합니다. 통합·하위 한도는 합산하지 않습니다.
- 모의 원장은 `source=SIMULATION`으로 조회합니다. 화면 필터는 승인·취소 행 유형을 기준으로 적용하고, 거래 상세는 행의 결제 ID를 사용합니다. 혜택 금액은 모의 승인 시점의 예상 혜택입니다. 현재 잔여 한도나 월별 혜택 총액 집계는 이 화면의 범위 밖입니다.

로컬 브라우저의 Vite 개발 서버에서는 기본적으로 예시 데이터를 사용합니다. 두 화면을 확인하려면 `frontend/`에서 `npm run dev`를 실행하고 **빠른결제 → 가상 포트폴리오 → 혜택**을 선택합니다. 2026년 11월에 합성 월간 상태와 거래가 표시됩니다. `VITE_BENEFITS_CONTEXT=demo`로 시연 API를 명시적으로 선택할 수 있고, `member`는 회원 세션과 동일 출처 구성이 필요합니다. 배포 빌드는 기본적으로 회원 문맥을 사용합니다.

관련 명세는 [보유 카드](../api/cards.md), [카드 상품](../api/products.md), [월간 상태](../api/monthly-states.md), [원장](../api/ledger.md), [모의 결제](../api/mock-payments.md)를 참고합니다.
