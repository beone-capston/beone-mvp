# FR-08 AI 보조: 완료 조건 매핑

[PRD FR-08](../PRD.md)의 요구와 완료 조건을 현재 무엇이 충족하고 무엇이 남았는지 정리합니다(결정 41 후보). 2026-11-25 develop 기준입니다.

**요지:**

- AI 초안은 계산 코드와 분리된 오프라인 도구로 만듭니다.
- 운영 계산은 처음부터 `VERIFIED` 규칙만 쓰므로, AI가 없어도 추천과 모의 승인은 이미 동작합니다.
- AI 초안 생성·비교·평가 측정은 아직 끝나지 않았습니다.

## 요구 매핑

| FR-08 요구 | 상태 | 근거 |
| --- | --- | --- |
| AI는 공식 약관에서 규칙 초안을 추출하고 필드별 원문 근거를 제시한다 | 진행 중 | 오프라인 도구 `tools/rule-draft`(PR #235, 검토 중). 아래 "AI 초안 도구" 참고. 실제 AI 호출은 사용자 승인 전이라 아직 없습니다. |
| 사람이 수정·승인하기 전에는 AI 출력으로 혜택 금액을 계산하거나 최종 카드를 선택하지 않는다 | 충족(구조) | 아래 "AI 출력이 계산에 들어가지 않는 구조" 참고 |
| AI는 업종 후보와 추천 설명을 보조할 수 있다 | 미구현(선택) | "할 수 있다" 항목입니다. 업종은 사용자나 시나리오가 확인한 코드만 받습니다([주문 도메인](../domains/order.md)). 추천 설명은 고정 문구를 씁니다. |
| AI 실패 시 사용자 업종 확인과 계산 결과 기반 기본 설명을 제공한다 | 충족(AI 없는 경로가 기본) | 서비스에 AI 호출이 없으므로 항상 이 경로입니다. 업종은 허용 목록 안의 확인된 코드로만 받습니다([주문 도메인](../domains/order.md)). 설명은 엔진 결과 코드를 문구로 바꿉니다([`RecommendationNotes`](../../backend/src/main/java/com/beone/api/recommendation/application/RecommendationNotes.java)). |
| 소비 예측은 필수 입력이 아니다 | 해당(미구현) | 소비 예측을 구현하지 않았습니다. 예정 소비는 월간 합계에 반영하지 않습니다(`RecommendationNotes.PLANNED_SPENDING_EXCLUDED`, D-18 K4). |

## 완료 조건 매핑

| 완료 조건 | 상태 | 근거와 남은 일 |
| --- | --- | --- |
| 공식 약관 원문 → AI 초안 → 사람의 수정·승인 → `VERIFIED` 반영 과정을 카드 4종에 대해 기록·시연한다 | 미완 | 아래 표 참고 |
| 카드 4종에 대해 수동 규칙 작성과 AI 초안 검토의 수정 항목·검토 시간을 비교한다 | 양식만 있음 | [평가 기록 양식](ai-draft-evaluation.md)(빈 표, 측정 방법). 과거 수동 작성 기록이 없어 수동 칸을 어떻게 채울지 결정이 필요합니다. |
| AI를 사용할 수 없어도 검증된 규칙으로 추천과 모의 승인이 가능하다 | 충족 | 아래 "AI 없이 동작하는 근거" 참고 |

첫째 완료 조건(기록·시연)의 단계별 상태입니다.

| 단계 | 상태 |
| --- | --- |
| 원문 | 4종 메타데이터는 [원문 스냅샷](sources.md)에 있습니다. |
| 수동 경로 | 규칙 4종이 모두 `VERIFIED`입니다([규칙 데이터 안내](README.md)). |
| AI 초안 | 도구는 [`tools/rule-draft`](../../tools/rule-draft/README.md)(PR #235)입니다. 실제 호출은 승인 전입니다. |
| 비교·승인 기록 | 도구의 `compare`·`approve` 명령이 있습니다(D41-2). 기록 위치는 [`reviews/`](reviews/README.md)이며 실제 카드 기록은 아직 없습니다. |
| 시연 기록 | 아직 없습니다. |

## AI 출력이 계산에 들어가지 않는 구조

| 장치 | 근거 |
| --- | --- |
| 계산은 `VERIFIED`만 선택 | [`RuleCatalog`](../../backend/src/main/java/com/beone/api/benefit/rule/RuleCatalog.java)는 판정일에 유효한 `VERIFIED` 규칙만 고릅니다. `AI_DRAFT`·후보·평가 전용 스냅샷은 보관만 하고 선택하지 않습니다. 시험: [`RuleCatalogTest`](../../backend/src/test/java/com/beone/api/benefit/rule/RuleCatalogTest.java)의 `neverSelectsUnverifiedRulesIncludingEvaluationOnlySnapshots`, `unverifiedVersionsMayOverlapAVerifiedOneWhichAloneIsSelected` |
| 상태 구분 | [`VerificationStatus`](../../backend/src/main/java/com/beone/api/benefit/rule/VerificationStatus.java)에 `AI_DRAFT`가 따로 있습니다. 운영 계산에는 `VERIFIED`만 씁니다. |
| 서비스에 AI 의존성 없음 | [backend `build.gradle`](../../backend/build.gradle)에 AI 제공자 SDK나 호출 코드가 없습니다. |
| AI 도구 분리(PR #235) | 도구는 backend와 분리된 독립 Gradle 프로젝트입니다. 동작은 다음과 같습니다.<br>- 초안 `status`를 `AI_DRAFT`로 고정합니다.<br>- 규칙 경로(`backend/src/main/resources/rules/`)에 쓰지 않습니다.<br>- `VERIFIED` 반영은 사람이 따로 커밋합니다. |

## AI 없이 동작하는 근거

서비스에는 AI 호출 경로가 없습니다. 그래서 "AI를 쓸 수 없을 때"가 따로 있지 않고, 아래 결정론적 경로가 항상 동작합니다. 결정론적 경로란 같은 입력이면 늘 같은 결과를 내는 코드 경로를 말합니다.

| 기능 | 경로 | 시험 |
| --- | --- | --- |
| 추천 계산 | [`RecommendationService`](../../backend/src/main/java/com/beone/api/recommendation/application/RecommendationService.java) → `RecommendationEngine`([`DefaultRecommendationEngine`](../../backend/src/main/java/com/beone/api/benefit/engine/DefaultRecommendationEngine.java)) → `RuleCatalog`의 `VERIFIED` 규칙 | [`DefaultRecommendationEngineTest`](../../backend/src/test/java/com/beone/api/benefit/engine/DefaultRecommendationEngineTest.java), 평가 사례 [`EvaluationCaseRunnerTest`](../../backend/src/test/java/com/beone/api/benefit/evaluation/EvaluationCaseRunnerTest.java) |
| 모의 승인 | [`SimulatedPaymentService`](../../backend/src/main/java/com/beone/api/payment/application/SimulatedPaymentService.java)가 승인 직전에 `RecommendationService.calculateForApproval`로 다시 계산합니다 | [`SimulatedPaymentServiceTest`](../../backend/src/test/java/com/beone/api/payment/application/SimulatedPaymentServiceTest.java), [`SimulatedPaymentIntegrationTest`](../../backend/src/test/java/com/beone/api/payment/SimulatedPaymentIntegrationTest.java) |
| 기본 설명 | 엔진의 결과 코드를 [`RecommendationNotes`](../../backend/src/main/java/com/beone/api/recommendation/application/RecommendationNotes.java)가 고정 문구로 바꿉니다 | 추천 웹·통합 시험 |

AI 기능(업종 후보·설명 보조)을 서비스에 추가하게 되면 이 표의 경로를 바꾸지 않습니다. AI 실패 시 이 경로로 돌아가는지를 그때 별도 시험으로 고정해야 합니다.

## AI 초안 도구 (PR #235, 검토 중)

develop에 병합되면 `tools/rule-draft/README.md`에 사용법이 있습니다. 병합 전 상태를 요약하면 다음과 같습니다.

- **입력:** 상품설명서 PDF 또는 쪽 표시 텍스트
- **출력:** 기존 규칙과 같은 키 구조의 초안, 필드별 원문 근거(쪽·인용)
- **검사:**
  - 키 구조: 기존 규칙 4개를 기준 표본으로 씁니다.
  - 근거: 인용문이 원문 해당 쪽에 그대로 있어야 확인된 근거로 칩니다.
- **실제 호출 조건:** `--live` 플래그와 키 환경 변수가 모두 있어야 합니다. 테스트는 녹화 응답만 쓰고 네트워크를 호출하지 않습니다.

## 문서 수정 제안 (관리자 판단)

이 PR은 PRD와 결정 기록을 수정하지 않습니다. 결정 41 기록은 관리자가 따로 정합니다. 아래는 제안입니다.

- **docs/decisions.md:** 결정 41 확정 시 다음 세 가지를 기록합니다.
  - "FR-08 AI 초안은 오프라인 도구, 서비스 업무 API 밖(D-14 유지)"
  - "PDF 원본 비공개 보관 기본안"
  - "AI 초안 status는 AI_DRAFT 고정, VERIFIED 반영은 사람의 별도 커밋"
- **docs/PRD.md FR-08:** 완료 조건 문구는 그대로 둡니다. "AI 초안 생성은 오프라인 도구로 한다"는 구현 방식을 덧붙일지만 검토합니다.
- **docs/rules/README.md:** 이 PR에서 원문 스냅샷·평가 양식·FR-08 매핑 링크를 추가했습니다.
