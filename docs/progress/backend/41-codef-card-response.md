## 2026-10-31 · CODEF 카드 응답 해석 경계 · 완료(PR 전)
- 한 일: 새 도메인 `codef`에 승인내역·보유카드·실적조회 응답 본문을 해석하는 `CodefCardResponseParser`와 결과 타입, 결과 코드 분류(`CodefResultCategory`)를 추가했습니다. 근거는 Aside의 브라우저로 공식 공개 문서를 렌더링해 수집한 본문 사본(수집 2026-10-31T12:00:47Z)입니다.
- 서비스에서 달라진 점: CODEF 응답을 받으면 추가 인증·토큰·인증서·통신·요청 형식·접근 설정·카드 확인 경로(지원 보류)·미분류를 구분하고, 단건·다건·0건·누락·형식 오류와 빈 값을 구분해 비민감 필드만 꺼낼 수 있습니다. 실제 호출·저장·추천 연결은 아직 없습니다.
- 지키는 조건: 당시 사본에 성공 코드 행이 없어(검색 범위에 따른 수집 누락) 성공 분류를 두지 않았습니다. 아래 2026-11-01 기록에서 보완했습니다. 빈 값은 0원·기본값이 아니고, 금액은 정수일 때만 숫자이며 음수 부호로 취소를 해석하지 않습니다. 카드번호·가맹점 연락처·세션·추가 인증 식별값·유효기간·결과 문구는 옮기지 않으며 결과 문자열에 나타나지 않습니다.
- 결정 기록: `CF-03002`인데 `continue2Way`가 불리언 `true`가 아니면 미분류(문서가 값의 존재와 `true` 여부로 판단하라고 하고 타입을 Boolean으로 적음). 중첩 목록의 빈 문자열은 값 없음, 최상위 `data`의 빈 문자열은 형식 오류(작업 지시서의 원시값 규칙).
- 검증: `./gradlew test`·`webTest`·`integrationTest`·`build`(각 `--rerun-tasks`) 결과는 PR에 기록합니다. 신규 테스트는 합성 응답이며 실제 응답 검증이 아닙니다.
- 남은 제한: HTTP·OAuth·요청 DTO·추가 인증 요청, 상태값 변환(D-04), 상품 매핑(D-01), 취소·부분취소 상세 반영, 오류 전체 목록 분류.

## 2026-11-01 · 성공 결과 코드 분류 보완 · 완료(PR 갱신)
- 한 일: `CodefResultCategory.SUCCESS`를 추가했습니다. 근거는 Aside의 브라우저로 공식 오류코드 페이지(https://developer.codef.io/common-guide/error-code)에서 CF-00000을 검색해 확인한 행(관찰 2026-11-01T07:10:00Z)이며, 기존 사본과 별개의 별첨입니다.
- 정정: 지난 기록의 "성공 코드는 사본에 없다"는 사본의 수집 누락이었고, 공식 문서에 성공 코드가 없다는 뜻이 아니었습니다.
- 서비스에서 달라진 점: `result.code`가 정확히 `CF-00000`이면 성공으로 분류합니다. 공백·대소문자·자릿수 차이·메시지 문구·코드 누락은 미분류입니다.
- 지키는 조건: 성공이어도 `data`의 누락·형식 오류·빈 값·해석 못 한 금액·목록 밖 코드는 그대로이며, 결과 코드와 데이터를 합치는 메서드를 두지 않았습니다. `CF-03002` 규칙은 바꾸지 않았습니다. 성공 분류는 실제 응답 검증·D-04 매핑·상품 확인이 아닙니다.
- 검증: 결과는 PR #42 본문에 기록합니다. 신규·변경 테스트는 합성 응답입니다.
- 남은 제한: HTTP·OAuth·전송 계약, 기관별 필수조건, 취소·부분취소 상세, 오류 전체 목록은 계속 미확인입니다.
