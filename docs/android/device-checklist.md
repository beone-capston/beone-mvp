# Android 실기기 확인 목록

사람이 실제 Android 기기에서 확인할 항목입니다. 단위 테스트, mock, 에뮬레이터 결과는 이 목록의 확인으로 인정하지 않습니다([PRD FR-06](../PRD.md), [D-08](../decisions.md#d-08-확정-정책)).

- 대상 기기: Samsung SM-S942N (Android 16, One UI 8.5), 지문 등록 + 화면 잠금 PIN (D-08)
- 설치: 사용자가 직접 `cd android && ./gradlew installDebug`로 설치합니다. 자동으로 기기에 설치·실행하지 않습니다.
- 실행: 런처의 **B:ONE 인증 점검** 아이콘(debug 빌드 전용)
- 기록: 결과를 PR 또는 이슈에 기기 모델·OS 버전·확인 날짜와 함께 적습니다. 생체·PIN 값이나 개인 정보가 보이는 화면은 첨부하지 않습니다.

### 확인 기록 (2026-10-28~29)

- 기기(이번 확인): Samsung SM-S942N, **Android 17**(SDK 37), One UI 9.0, 보안 패치 2026-09-05, 빌드 `CP2A.260605.016.S942NKSU4BZI6`
- 비교: [과거 PoC](../d08-biometrics-poc.md)와 D-08은 같은 모델의 Android 16(API 36), One UI 8.5, 보안 패치 2026-08-05, 빌드 `BP4A.251205.006.S942NKSS4AZHA` 기록입니다. PoC에는 기기 일련번호가 없어 같은 기기인지는 확인하지 않았습니다. 이번 결과는 Android 17 기준이며 과거 PoC 기록을 대신하지 않습니다.
- 빌드: debug, 커밋 `0b1cc3f`. 사용자가 무선 디버깅으로 연결하고 설치·실행을 승인했습니다.
- 방법: 지문·PIN·홈 이동·회전 등 조작은 사용자가 직접 했습니다. 점검 화면의 문구(`uiautomator`)와 Activity 생명주기 이벤트(`logcat -b events`)를 시각과 함께 기록해 대조했습니다. 1·4·5·14번과 15번의 "홈으로 나갈 때 인증 창이 떠 있었음"은 화면 기록 간격(약 3초) 사이에 지나가 사용자 보고를 함께 근거로 삼았습니다. 12번은 다크 모드 전환 뒤 활성 유지까지 기록했고, 남은 초가 이어지는 것은 같은 화면 재생성 경로인 11번에서 수치로 확인했습니다. 각 항목은 1회씩 확인했습니다. 앱 crash·ANR 기록은 없었습니다.
- 확인된 동작:
  - 8번: PIN 입력 중 Activity의 `onPause`·`onStop`이 생기지 않아 PIN 입력이 앱 이탈로 처리되지 않았습니다.
  - 6번: 남은 시간이 약 20초일 때 재인증에 성공하자 60초로 다시 시작했습니다(80초가 아님).
  - 11·13번: 회전 때 Activity가 다시 만들어져도 활성 상태와 진행 중인 인증 결과가 유지됐고, 회전만으로 인증 창이 다시 뜨지는 않았습니다.
- 15번 기대 문구 정정: 복귀 화면 문구가 `앱을 벗어나 비활성화`가 아니라 `인증이 취소되어 비활성화`였습니다(2026-10-29 사용자 결정으로 코드 유지, 문구만 정정).
  - 원인 판단: 취소 결과가 `onStop`보다 먼저 처리된 것으로 봅니다. `onStop` 뒤에 온 결과는 무시되므로, 취소가 나중에 왔다면 `앱을 벗어나 비활성화`가 남았어야 합니다. 시스템이 보낸 오류 코드와 정확한 도착 시각은 앱이 기록하지 않아 확인하지 않았습니다.
  - 기존 요구는 그대로입니다. 앱 이탈 뒤 비활성, 진행 중 인증 종료, 복귀 뒤 재인증 가능은 실기기에서 확인했습니다(복귀 시 인증 창 없음 → 다시 [기기 인증]으로 활성). **앱 이탈 뒤 늦게 도착한 성공의 무시**는 이번 실기기 순서에서는 일어나지 않아 실기기로 확인하지 못했고, 단위 테스트로만 확인한 상태입니다.

### 관측 로그 수집 방법 (debug 전용)

- debug 빌드에서만 태그 `BeoneAuthTrace`(INFO)로 한 줄씩 남습니다. release에는 기록 구현이 없습니다. 구성은 [기기 인증 안내](auth-session.md#관측-기록-debug-전용)를 봅니다.
- 수집(앱 태그만, 로그 버퍼를 지우는 `-c`는 쓰지 않음): `adb logcat -v threadtime -T 1 -s BeoneAuthTrace:I`. 버퍼에 남은 것만 볼 때는 `adb logcat -d -v threadtime -s BeoneAuthTrace:I`
- 기기 버퍼는 짧은 시간에 순환하므로 시험 중 파일로 받아 둡니다. 원문은 저장소에 넣지 않고 저장소 밖 로컬(운영 기록)에 보관합니다. 문서에는 개인 정보·기기 식별 정보가 없는 요약과 짧은 발췌만 적습니다.
- 발췌(구간 B, 인증 창이 떠 있는 동안 홈으로 이탈한 한 회차):

```text
t=160734334 seq=17 ev=BEGIN from=IDLE to=AUTHENTICATING req=3
t=160734339 seq=18 ev=DISPATCH from=- to=- req=3 result=SENT_TO_LIBRARY
t=160736350 seq=19 ev=CALLBACK from=- to=- req=- cb=ERROR code=10
t=160736350 seq=20 ev=RESULT from=AUTHENTICATING to=IDLE req=3 kind=CANCELED code=10 terminal=true applied=true
t=160736361 seq=22 ev=LIFECYCLE from=- to=- req=- cb=ON_PAUSE inst=1
```

`req`는 앱 내부 순번으로, 로그를 서로 맞춰 보기 위한 표식입니다. 그 콜백이 해당 요청의 것이라는 증거가 아닙니다.

## 다음 시험 준비: 설치본 확인과 남은 항목 (2026-10-31, 미실행)

위 확인 기록의 "커밋 전" 코드는 이후 커밋 `08ee320`에 들어갔습니다. 2026-10-31에 `08ee320`과 `android/` 트리가 같은 커밋(`e9c7746`, 최신 `develop` merge)에서 debug APK를 다시 만들었고, sha256이 구간 B APK `d9977fd7…`와 같았습니다. 그 뒤에는 단위 테스트만 추가했습니다. 아래는 사용자가 바로 실행할 수 있게 정리한 절차이며, 이 문서 작성 시점까지 실행하지 않았습니다.

2. **APK 해시 기록:** `android/`에서 `./gradlew clean assembleDebug`를 실행한 뒤, 저장소 루트에서 `shasum -a 256 android/app/build/outputs/apk/debug/app-debug.apk`를 기록합니다. 증분 빌드는 해시가 다를 수 있어 `clean`을 씁니다. 시험한 커밋 SHA도 함께 적습니다.
3. **설치와 설치본 대조:** 저장소 루트에서 `adb install android/app/build/outputs/apk/debug/app-debug.apk` → `adb shell pm path com.beone.app`이 알려준 경로를 저장소 밖 폴더로 `adb pull`해 sha256을 2와 비교합니다. 다르면 그 설치로는 시험하지 않고 다시 설치합니다.
4. **실행 확인:** 런처에 **B:ONE 인증 점검** 아이콘이 있어야 합니다(WebView 셸 APK에는 없음).
5. **기록:** 항목마다 판정 용어(위 확인 기록과 같음), 기기 모델·OS 버전, APK sha256, 커밋 SHA를 적습니다. 로그를 받을 때는 [관측 로그 수집 방법](#관측-로그-수집-방법-debug-전용)을 따릅니다.
